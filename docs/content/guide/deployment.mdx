生产部署使用一个 Cloudflare Worker。Worker 在 `/` 呈现动态站点，在 `/api/` 处理 HTTP、WebSocket 与 SSE 请求，在 `/upload-img/` 读取 R2，并提供 `/admin/` 与 `/docs/` 的静态资源。

## 更新已有站点

在已安装依赖、已授权的项目目录中，使用原 Cloudflare 账号和 Worker 名称。以下命令更新名为 `my-joiask` 的站点。

```sh
npm run deploy -- --name my-joiask
```

使用仓库默认 Worker 名称的站点可直接运行 `npm run deploy`。部署命令会构建站点、应用 D1 迁移并发布，继续使用现有的 Worker 密钥和 D1 中的管理员账号。

## 首次部署与管理员

### 准备资源

准备支持 D1、R2、Durable Objects 和 Queues 的 Cloudflare 账号并启用 R2。使用 Node.js 24，在仓库根目录安装依赖。如在本机初次使用 Wrangler，再登录目标账号。

```sh
npm ci
npx wrangler login
```

站长需要为 `SESSION_SECRET` 和 `SETTINGS_KEY` 分别准备独立的随机密钥，每个至少 32 字节。如果目标 Worker 已在控制台配置这两个长期 Secret，首次发布 JoiAsk 也可直接使用上面的更新命令。通过命令行提供密钥时，准备一个私有文件（例如仓库根目录的 `.dev.vars.production`），按每行一个 `名称=值` 的格式填写两项。将文件保存在受限位置并妥善备份。

### 构建与发布

选择目标 Worker 名称。以下命令使用自备的密钥文件首次发布到 `my-joiask`。

```sh
npm run deploy -- --name my-joiask --secrets-file .dev.vars.production
```

部署命令会按仓库根目录的 `wrangler.jsonc` 准备资源。CI 可使用有相应资源权限的 Cloudflare API token 与账号 ID 授权。如果使用仓库的 Cloudflare 部署按钮，可在安装时提供上述两个 Worker 密钥，发布完成后继续设置管理员。

### 在控制台设置首个管理员

1. 在 **Workers & Pages** 中打开目标 Worker，前往 **Settings → Variables and Secrets**，点击 **Add**。
2. 添加 `JOIASK_INITIAL_ADMIN_USERNAME`，填入自选管理员名。类型可选 **Text**，普通访客无法从站点读取该变量。希望在控制台隐藏用户名时选 **Secret**。再添加 `JOIASK_INITIAL_ADMIN_PASSWORD`，类型选 **Secret**，填入自选密码。点击 **Deploy** 使设置生效。
3. 访问该站点的 `/admin/`，使用这组凭据完成首次登录。成功后可以在同一设置页移除这两项，并点击 **Deploy**。请长期保留 `SESSION_SECRET` 和 `SETTINGS_KEY`。[Cloudflare 的 Worker Secret 操作指南](https://developers.cloudflare.com/workers/configuration/secrets/#via-the-dashboard)

需要在首次发布时由命令行创建账号，或给已有站点重置管理员密码，可参阅[管理员指南](./administrators.mdx)。

## 发布选项

发布前可运行 `npm run deploy -- --name my-joiask --dry-run` 在本地生成发布包。自定义域名可在目标 Worker 的设置中绑定。构建前设置 `SITE_ORIGIN`（例如 `https://ask.example.com`），可以为文档站点地图生成对应域名的绝对链接。远端管理命令也使用相同的 `--name my-joiask`，以选中该站点的 D1。

## 上线验证与回退

访问首页、管理后台和本文档，检查站点标题、登录与投稿；上传测试图片并观察另一个浏览器中的实时表情。生产 SMTP 与 B 站签名读取需要从实际 Worker 的出口验证。变更数据库前导出 D1 备份，发布兼容的结构迁移后再切换 Worker 版本。Workers 的版本回退只改变代码，已写入的 D1 和 R2 数据需要单独处理。
