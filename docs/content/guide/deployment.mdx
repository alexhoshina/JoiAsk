生产部署使用一个 Cloudflare Worker。Worker 在 `/` 呈现动态站点，在 `/api/` 处理 HTTP、WebSocket 与 SSE 请求，在 `/upload-img/` 读取 R2，并提供 `/admin/` 与 `/docs/` 的静态资源。

## 准备资源

使用支持所需绑定的 Cloudflare 账号，配置 D1、R2、Durable Objects 和 Queues。仓库根目录的 `wrangler.jsonc` 定义资源名称。使用 `npx wrangler login` 授权，或在 CI 配置有对应资源权限的 Cloudflare API token 与账号 ID。生产会话密钥和设置加密密钥各自使用独立随机值。

## 构建与发布

```sh
npm ci
npx wrangler login
node -e "const { randomBytes } = require('node:crypto'); const key = () => randomBytes(32).toString('hex'); require('node:fs').writeFileSync('.dev.vars.production', 'SESSION_SECRET=' + key() + '\nSETTINGS_KEY=' + key() + '\n', { flag: 'wx', mode: 0o600 })"
```

### 首次部署与管理员

新 D1 只在首次部署时接受可选的管理员凭据。要在发布时创建超级管理员，请在运行 `npm run deploy` 的终端或 CI 部署步骤中同时设置 `JOIASK_INITIAL_ADMIN_USERNAME` 和 `JOIASK_INITIAL_ADMIN_PASSWORD`。在 CI 中将密码作为该步骤的保密环境变量注入。`--secrets-file` 文件中只放 Worker 运行所需的 `SESSION_SECRET` 和 `SETTINGS_KEY`。

以下 Bash 示例在子 shell 内输入密码并关闭命令跟踪。部署命令结束后，两个变量随子 shell 一起释放。

```bash
(
  set +x
  export JOIASK_INITIAL_ADMIN_USERNAME=site-admin
  IFS= read -rs -p '首个管理员密码：' JOIASK_INITIAL_ADMIN_PASSWORD || exit 1
  printf '\n'
  export JOIASK_INITIAL_ADMIN_PASSWORD
  npm run deploy -- --secrets-file .dev.vars.production
)
```

也可以直接运行 `npm run deploy -- --secrets-file .dev.vars.production`，发布后再用管理员 CLI 创建账号。新库初始化时只填写一项会提示错误，请同时提供两项或都留空。初始化完成后可移除 CI 中的两个管理员变量，已有站点创建账号或重置密码请使用[管理员 CLI](./administrators.mdx)。

保管好首次生成的密钥文件。后续发布复用相同的密钥，运行 `npm run deploy`。如果通过 `npm run deploy -- --name my-joiask --secrets-file .dev.vars.production` 指定 Worker 名称，远端管理命令也应携带 `--name my-joiask`，以选中该部署的 D1。发布前可以运行 `npm run deploy -- --dry-run` 在本地生成发布包。如果需要通过自定义域名访问，在 Cloudflare Workers 设置中绑定域名。构建前可以设置 `SITE_ORIGIN`（例如 `https://ask.example.com`），用于生成文档站点地图中的绝对链接。

## 上线验证与回退

访问首页、管理后台和本文档，检查站点标题、登录与投稿；上传测试图片并观察另一个浏览器中的实时表情。生产 SMTP 与 B 站签名读取需要从实际 Worker 的出口验证。变更数据库前导出 D1 备份，发布兼容的结构迁移后再切换 Worker 版本。Workers 的版本回退只改变代码，已写入的 D1 和 R2 数据需要单独处理。
